# نظام إدارة التوزيع — ERP

نظام ERP بالعربي (RTL) لشركة استيراد وتوزيع مصرية: مشتريات بعملات أجنبية مع مصاريف
استيراد، مخازن، مبيعات للتجار، تحصيلات، مندوبين، وتقارير.

**Laravel 13 · Inertia v3 · Vue 3 + TypeScript · Tailwind v4 · MySQL (InnoDB)**

---

## التشغيل

```bash
composer install
npm install
cp .env.example .env && php artisan key:generate
php artisan migrate --seed
npm run dev
```

### وضعين للبيانات

| الأمر                                     | بيعمل إيه                                                                                                                  |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `php artisan db:seed`                    | **نظام فاضي للتسليم**: 3 مستخدمين بأدوارهم وفريق الشركة وبس. **ولا مخزن ولا تصنيف ولا صنف ولا تاجر ولا مورد ولا أي حركة.**       |
| `php artisan db:seed --class=DemoSeeder` | **بيانات تجريبية كاملة**: 2 مخازن، 6 تصنيفات، 40 صنف، 5 موردين، 25 تاجر، 4 مندوبين، و3 شهور حركة بيع وشراء وتحصيل ومرفقات. |

الوضع الافتراضي مكتوب من غير `factory()` ولا `fake()`، فبيشتغل على السيرفر بعد
`composer install --no-dev` (مكتبة Faker موجودة في `require-dev` بس). وآمن لو
اتشغّل أكتر من مرة — بيتخطّى أي مستخدم موجود.

`DemoSeeder` بيمسح بيانات النظام الأولى قبل ما يشتغل، فينفع تشغّله فوق النظام
الفاضي على طول — المستخدمين ما بيتمسوش.

### أصناف العميل

```bash
php artisan db:seed --class=ClientProductsSeeder
```

سيدر مستقل **مش** مربوط بـ `DatabaseSeeder`، بيضيف أصناف العميل الحقيقية في
تصنيف «إكسسوارات ستائر»، ومعاها الأسماء اللي المسح بيطلّعها عشان أول فاتورة
تتمسح تطابق على طول.

آمن على السيرفر: بيحدّث الصنف بكوده، وما بيلمسش أي بيانات تانية. **والأسعار
مش في قايمة التحديث** — الصنف الجديد بياخد صفر، والموجود بيحتفظ بالأسعار اللي
العميل حطّها من الشاشة، فتشغيله تاني ما بيمسحش شغله.

### البدء من نظام فاضي

كل شاشة بتعرض حالة فاضية بالعربي مع زرار إجراء بدل أصفار ورسوم فاضية، ولوحة
التحكم بتعرض خطوات التشغيل. أول خطوة عملية هي **المخازن** من القائمة الجانبية
← «أضف أول مخزن»، لأن كل حركة شراء أو بيع لازم تتسجّل على مخزن.

## قواعد مهمة في البيانات

- **رصيد المخزن = مجموع حركات المخزون** (`stock_movements`)، مفيش عمود رصيد مخزّن.
- **الرصيد مش هو المتاح.** المتاح = الرصيد ناقص المحجوز بطلبات التحضير
  المفتوحة أو المحضّرة. كل الشاشات بتعرض المتاح، وفاتورة البيع بتتفحص
  عليه.
- فواتير الشراء بعملتها + `exchange_rate` للتحويل للجنيه. `stock_movements.unit_cost`
  **دايمًا بالجنيه** بعد توزيع مصاريف الاستيراد على البنود.
- أرصدة الموردين بعملة المورد؛ أرصدة التجار ومصاريف الاستيراد بالجنيه.
- عمولة المندوب بتتحسب **على المحصّل** مش على المبيعات.
- كل الأرقام بأرقام لاتينية (0-9) والتواريخ بصيغة «13 نوفمبر 2026».
- توقيت التطبيق `Africa/Cairo` (يتغيّر من `APP_TIMEZONE` في `.env`).

## سيرفر الـ MCP — ربط كلود بالبيانات

النظام فيه سيرفر [MCP](https://modelcontextprotocol.io) **للقراءة فقط**، بيدّي كلود
القدرة إنه يجاوب على أسئلة زي «مين أكبر المديونيات؟» أو «إيه اللي ناقص من المخزن؟»
من غير ما يقدر يعدّل أي حاجة. كل الأدوات متعلّمة `readOnlyHint`.

### الأدوات

| الأداة                  | بتعمل إيه                                                          |
| ---------------------- | ------------------------------------------------------------------ |
| `low-stock-products`   | الأصناف تحت حد الطلب والناقص من كل صنف                              |
| `trader-balance`       | رصيد تاجر، المحصّل منه، وحالته مع حد الائتمان                        |
| `top-debtors`          | أكبر المديونيات + إجمالي المستحق على كل التجار                     |
| `sales-summary`        | مبيعات فترة مقسّمة باليوم أو بالشهر                                 |
| `top-products`         | أكتر الأصناف مبيعًا بالقيمة أو بالكمية مع هامش الربح                 |
| `stock-lookup`         | رصيد صنف في كل مخزن + التكلفة وسعر البيع                           |
| `invoice-lookup`       | تفاصيل فاتورة برقمها: البنود، الإجماليات، وحالة الفاتورة الإلكترونية |
| `slow-moving-products` | الأصناف الراكدة وقيمة الفلوس النايمة فيها                           |
| `fast-moving-products` | أكتر الأصناف حركة — بالكمية أو الإيراد أو الدوران                    |
| `forecast-needs`       | المتوقّع ينقص في 30 يوم، مع تحذير لو التاريخ قصير                   |
| `sales-breakdown`      | المبيعات باليوم/الأسبوع/الشهر + التغيّر عن الفترة السابقة            |
| `sales-decline`        | مقارنة فترتين وأكبر النزول بالصنف والتاجر والمندوب                 |
| `best-customers`       | أحسن التجار بالمبيعات أو المحصّل أو سرعة السداد                     |
| `reps-comparison`      | مقارنة المندوبين: مبيعات، محصّل، مستحق، عمولة                       |
| `company-overview`     | لقطة واحدة: مبيعات الشهر، المستحق، قيمة المخزون، النواقص           |

### الاتصال

السيرفر على `POST https://erp.usi-eg.com/mcp/erp`، ومحمي بجارد Passport واحد
(`auth:api`) بيقبل طريقتين للتوكن.

#### 1) claude.ai على الويب — Custom Connector (OAuth 2.1)

في claude.ai: **Settings → Connectors → Add custom connector**، والصق:

```
https://erp.usi-eg.com/mcp/erp
```

كلود بيكتشف الباقي لوحده: بيقرا `/.well-known/oauth-protected-resource/mcp/erp`،
بيسجّل نفسه على `/oauth/register`، وبيحوّلك على `/oauth/authorize` — تدخل
بحساب النظام وتضغط **«اسمح بالوصول»**، وبترجع لكلود متوصّل.

المسارات اللي `Mcp::oauthRoutes()` بتسجّلها:

| المسار                                          | وظيفته                                 |
| ----------------------------------------------- | -------------------------------------- |
| `/.well-known/oauth-protected-resource/mcp/erp` | بيقول لكلود مين سيرفر التصاريح         |
| `/.well-known/oauth-authorization-server`       | عناوين authorize/token/register + PKCE |
| `POST /oauth/register`                          | تسجيل العميل تلقائيًا (RFC 7591)        |
| `GET /oauth/authorize`                          | شاشة الموافقة العربية                  |
| `POST /oauth/token`                             | تبديل الكود بتوكن (PKCE S256)          |

نطاقات الـ redirect المسموح بيها محصورة في `config/mcp.php` على `claude.ai`
و `claude.com` و localhost.

#### 2) Claude Code — توكن شخصي

```bash
php artisan erp:mcp-token admin@erp.test
```

الأمر بيطبع التوكن **مرة واحدة بس** ومعاه سطر الربط الجاهز:

```bash
claude mcp add --transport http erp https://erp.usi-eg.com/mcp/erp \
  --header "Authorization: Bearer <التوكن>"
```

#### محليًا من غير توكن (stdio)

```bash
php artisan mcp:start erp
php artisan mcp:inspector erp
```

### النشر على استضافة مشتركة

النشر المعتاد: `git pull` → `composer install` → `php artisan migrate`.
بعد أول نشر بس، شغّل مرة واحدة:

```bash
php artisan erp:mcp-setup
```

بيولّد مفاتيح Passport (مش بتتحط في git) وبيعمل عميل التوكنات الشخصية.
آمن لو اتشغّل تاني — بيعمل الناقص بس.

ولو بتعمل `config:cache` على السيرفر، شغّل `php artisan optimize:clear` بعد
أول نشر عشان إعدادات الجارد الجديدة تتقري.

**شروط لازم تتحقق على السيرفر:**

- `ext-sodium` مفعّلة في PHP (Passport محتاجها). تأكد بـ `php -m | grep sodium`.
- `APP_URL=https://erp.usi-eg.com` في `.env` — روابط اكتشاف الـ OAuth بتتبني منها.
- الملفات المبنية (`public/build`) بتتعمل لها commit من الجهاز المحلي لأن
  السيرفر مافيهوش Node.

## المساعد الذكي

النظام فيه مساعد مبني على [Prism](https://prismphp.com) بيشتغل على **Gemini**
(الطبقة المجانية) افتراضيًا، و**Claude** اختيار تاني. كله نداءات HTTP عادية من
السيرفر من غير streaming، عشان الاستضافة المشتركة مقفول فيها `exec` و
`proc_open` ومفيهاش Node.

### إعدادات `.env`

| المفتاح                  | الافتراضي   | بيعمل إيه                                                     |
| ------------------------ | ---------- | ------------------------------------------------------------- |
| `ERP_AI_ENABLED`         | `true`     | `false` بيخفي أزرار المساعد كلها                              |
| `ERP_AI_PROVIDER`        | `gemini`   | `gemini` أو `anthropic`                                       |
| `ERP_AI_CHAT_MODEL`      | حسب المزوّد | موديل المحادثة — سيبه فاضي ياخد الافتراضي                      |
| `ERP_AI_VISION_MODEL`    | حسب المزوّد | موديل قراءة الفواتير                                          |
| `ERP_AI_MAX_TOKENS`      | `2048`     | أقصى طول للرد                                                 |
| `ERP_AI_CHAT_RATE_LIMIT` | `20`       | أسئلة في الدقيقة لكل مستخدم                                   |
| `ERP_AI_SCAN_RATE_LIMIT` | `6`        | فواتير ممسوحة في الدقيقة لكل مستخدم                           |
| `ERP_AI_FALLBACK_MODEL`  | حسب المزوّد | بديل لما الأساسي يتأخر أو يرجّع 503 أو 404 — **لازم موديل تاني** |
| `ERP_AI_TIMEOUT`         | `20`       | مهلة نداء واحد بالثواني                                       |
| `ERP_AI_BUDGET`          | `25`       | ميزانية الطلب كله — لازم تحت حد PHP (~30)                      |
| `ERP_AI_ROUTING_MODEL`   | حسب المزوّد | موديل توجيه السؤال لمجاله — الأخف دايمًا                        |
| `ERP_AI_ROUTING_TIMEOUT` | `6`        | مهلة نداء التوجيه لوحده                                       |
| `ERP_AI_ROUTING_RESERVE` | `10`       | أقل وقت فاضل يستاهل ننفق منه على توجيه                        |
| `ERP_AI_STARTERS`        | `6`        | عدد الأسئلة المقترحة في اللوحة                                 |
| `GEMINI_API_KEY`         | —          | لازم لما المزوّد `gemini`                                       |
| `ANTHROPIC_API_KEY`      | —          | لازم لما المزوّد `anthropic`                                    |

الموديل الافتراضي بيتغيّر مع المزوّد لوحده. على جيميني:

| الاستخدام   | الموديل                 | الوقت للنداء الواحد |
| ---------- | ----------------------- | ------------------- |
| المحادثة   | `gemini-3.5-flash-lite` | أقل من ثانية        |
| مسح فاتورة | `gemini-3.5-flash`      | ~14 ثانية           |
| البديل     | `gemini-3.1-flash-lite` | أقل من ثانية        |

الأرقام دي مقاسة على السيرفر الفعلي. المحادثة على الموديل الخفيف عن قصد:
الرقم في الرد جاي من الأداة أصلاً مش من الموديل، فالفرق في الجودة مش
محسوس، و14 ثانية للنداء الواحد معناها إن سؤال بجولة أدوات واحدة بياكل
الميزانية كلها. المسح فضل على الموديل الأكبر لأن صورة خط اليد المايلة
محتاجاه، وهو نداء واحد مش دورة.

#### البديل لازم يكون موديل تاني

البديل بيتجرّب لما الأساسي يرجّع 503 (مزحوم) أو 404 أو يتأخر. والموديل
المزحوم هيرجّع 503 تاني — فبديل بنفس اسم الأساسي معناه **إن مفيش بديل
أصلاً**.

وده اللي حصل على السيرفر: المحادثة والبديل الاتنين كانوا
`gemini-3.5-flash-lite`، فلما الموديل اتزحم، التلات محاولات كلها راحت
لنفس الموديل المزحوم ووقعت ورا بعض، والمستخدم شاف «المساعد مش متاح» من
غير ما يكون فيه أي محاولة حقيقية على موديل تاني.

دلوقتي الافتراضي `gemini-3.1-flash-lite` — جيل أقدم ومستقر ومش بيتزحم مع
`3.5`. ولو حد ظبّط `ERP_AI_FALLBACK_MODEL` بنفس الأساسي على السيرفر،
`AiService` بياخد أول موديل مختلف من `alternates` في `config/ai.php`
وبيكتب تنبيه في اللوج — فالإعداد الغلط مابيسكتش النظام.

وعلى كلود `claude-haiku-4-5` (أرخص موديل عندهم) والبديل `claude-sonnet-5`
— أكبر، بس مابيتستعملش غير لما Haiku يزحم. يعني التبديل لكلود سطرين بس:

```dotenv
ERP_AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
```

المفاتيح بتتقرا على السيرفر بس وعمرها ما بتتبعت للمتصفح.

### «اسأل السيستم» — شات واحد بيوجّه نفسه

زرار ✨ في الشريط العلوي بيفتح **لوحة محادثة واحدة** بتتسأل فيها أي حاجة.
مفيش تبويبات يختار منها المستخدم: هو عنده سؤال، مش عنده تصنيف.

التقسيم موجود، بس بقى وراها. قبل كل إجابة بيحصل **نداء تصنيف صغير**
(`AgentRouter`) على الموديل الخفيف — تعليمات سطور، من غير أدوات، ورده
كلمة أو اتنين — بيقول السؤال ده بيخص أنهي مجال، وبنبعت أدوات المجال ده بس:

| المجال        | بيجاوب على                                 | الأدوار       |
| ------------- | ------------------------------------------ | ------------ |
| **المخازن**   | النواقص، الراكد، سريع الحركة، المتوقّع يخلص | الكل         |
| **المبيعات**  | الأداء، أسباب النزول، التجار، المندوبين     | الكل         |
| **المشتريات** | نطلب إيه، وفواتير الموردين                 | مدير + محاسب |
| **الإدارة**    | مين عمل إيه، الدخول، الصورة الكبيرة        | مدير بس      |

- **السؤال اللي على أكتر من مجال بياخدهم كلهم.** «مين أكتر تاجر عليه فلوس
  وإيه الأصناف اللي قربت تخلص؟» بتروح بأدوات المبيعات والمخازن مع بعض.
- **سؤال المتابعة بيفضل في مجاله.** «وآخر دفعة؟» لوحده مالوش معنى — الموجّه
  بياخد مجال السؤال اللي فات ومابيغيّروش غير لو السؤال الجديد واضح إنه
  على حاجة تانية.
- **التوجيه عمره ما بيوقّع السؤال.** يفشل، أو يرد كلام مش مفهوم، أو الوقت
  يضيق عليه — المستخدم بياخد رده برضه: من آخر مجال اتكلم فيه، وإلا من
  مجموعة افتراضية مختصرة (النواقص، ملخّص المبيعات، المديونيات، بحث
  الفواتير، واللقطة العامة).
- **الصلاحية فوق التوجيه.** الموجّه بيشوف المجالات اللي الدور بيوصلها بس،
  ولو رد بمجال ممنوع بيتشال في صمت — والمجموعة الافتراضية نفسها بتتصفّى
  على أدوات الدور.
- **الأسئلة المقترحة مخلوطة**: ستة أسئلة من كل المجالات اللي الدور بيوصلها،
  عشان أول نظرة تقول للمستخدم إنه يسأل أي حاجة.

التعريفات (التعليمات + الأدوات) فاضلة في الكود في `app/Ai/Agents` — التوجيه
بيتظبّط بسطر في `toolClasses()`، مش من لوحة إعدادات.

ليه نداء زيادة أصلاً؟ لأن وصف كل أداة بيتبعت مع كل جولة: تمنتاشر أداة في
السلّة معناها تعليمات أطول، ووقت أطول على استضافة بتقطع بعد 30 ثانية،
واحتمال أكبر إن الموديل يختار الأداة الغلط. نداء التصنيف على flash-lite
أقل من ثانية — أرخص من الجولة الزيادة اللي الاختيار الغلط بيسبّبها.
والنداءين بيتقاسموا **ميزانية واحدة** (25 ثانية)، فالمجموع بيفضل تحت حد PHP.

**القاعدة الذهبية**: كل رقم بيتحسب في PHP جوه الأداة. الموديل بيشرح
ويوصّي بس — ممنوع يجمع أو يطرح أو يقدّر. لو الرقم مش في رد الأداة،
بيقول إنه مش متاح.

- بيستعمل **نفس أدوات سيرفر الـ MCP** بالظبط — `App\Ai\ErpToolkit` بيقرا قايمة
  أدوات `ErpServer` ويلفّها لـ Prism. أي أداة جديدة تتضاف للسيرفر بتبقى متاحة
  في المحادثة لوحدها، والاتنين بيفضلوا متفقين على نفس الأرقام.
- كل الأدوات **قراءة فقط**، فالمحادثة ما تقدرش تعدّل أي حاجة مهما اتسألت.
- المحادثة محفوظة في **الجلسة** — بتفضل وانت بتتنقّل بين الشاشات، وبتتمسح مع
  تسجيل الخروج.

### «مسح فاتورة» — من صورة لمسودة

زرار في صفحة **فاتورة شراء جديدة** و**فاتورة بيع جديدة**: ترفع صورة الفاتورة
أو PDF (أقل من 8 ميجا)، والنظام يقرا منها المورد/التاجر والتاريخ والعملة
وسعر الصرف والبنود والخصم ومصاريف الاستيراد، **ويملا الفورم العادي**.

- **مفيش حاجة بتتحفظ من المسح.** الفورم بيتملا وبس، والحفظ بيفضل على زرار
  الحفظ العادي بعد ما تراجع.
- **المطابقة بتحصل على السيرفر مش في الموديل.** الموديل بيقرا الورق بس —
  عمره ما بيشوف جدول الأصناف ولا بيرجّع `id`. الأصناف بتتطابق بالكود الأول
  وبعدين بالاسم، والموردين والتجار بالاسم (مفيش عمود كود عندهم) وبعدين
  بالتليفون. المقارنة بتعدّي على تطبيع عربي، فـ«شركه النور» تطابق
  «شركة النور».
- **اللي مش متأكد منه بيتلوّن أصفر** مع اللي مكتوب على الورق تحته، وتقدر
  تختار الصنف أو التاجر الصح من القايمة. اللون بيروح أول ما تعدّل الخانة.

#### الأسماء البديلة — إزاي النظام بيتعلّم خط العميل

فواتير العملاء مكتوبة بخط اليد، والاسم على الورق نادرًا ما بيطابق اسم
الكتالوج: «كبولى محوز» مقابل «كبولي مجوز». أول ما تصحّح المطابقة في
مسودة، الاسم اللي كان على الورق بيتحفظ في `product_aliases` (والتجار في
`customer_aliases`)، والمسح الجاي بيطابقه **قبل** أي مقارنة تانية.

يعني الصنف اللي بتصحّحه النهارده مابيتسألش عنه تاني. الأسماء دي بتتعرض
على صفحة الصنف (المخزون ← الصنف) وتقدر تضيف أو تشيل منها بإيدك.

#### الفواتير المكتوبة بخط اليد

تعليمات الموديل متظبّطة على شكل دفتر العميل بالظبط — تلات خانات
(الكمية / اسم العميل والصنف / السعر)، **اسم العميل في أول سطر من خانة
الصنف** مش في خانة لوحده، «ك» تعني كرتونة، والسعر ساعات بيبقى للجوز.
والصورة المايلة أو المقلوبة ٩٠ درجة بتتقرا عادي. الخط الوحش بيترجع
بأقرب قراءة متعلّمة «محتاجة مراجعة» بدل ما السطر يتساب فاضي.

**الكمية والسعر بيترجعوا نص مش رقم.** على الورق الخانة نادرًا ما بتبقى
رقم نضيف: «٣ ك»، «٤٠ ج»، «٦٠ الجوز». لما الـ schema كان بيطلب رقم،
الموديل مكانش بيلاقي رقم صالح يرجّعه فكان بيسيب الخانة فاضية — وعمود
السعر كله كان بيرجع فاضي. دلوقتي بياخد النص زي ما هو، و
`ArabicText::number()` بيطلّع الرقم منه على السيرفر.

**اسم العميل مابيتاخدش من سطر صنف.** لو الاسم اللي الموديل رجّعه موجود
برضه في قايمة الأصناف، يبقى خد سطر منهم بالغلط — فالنظام بياخد **أول**
سطر كاسم عميل ويشيله من الأصناف. خمس سطور بيطلعوا عميل و٤ أصناف.

**لو الفاتورة اتفتحت بالنوع الغلط** (فاتورة بيع اتمسحت من شاشة
المشتريات أو العكس)، الاسم بيكشفها: تاجر في فاتورة شراء أو مورد في
فاتورة بيع. بيظهر تنبيه عربي وزرار «حوّلها لفاتورة بيع/شراء» —
والتحويل بيعيد المطابقة من نفس القراءة من غير ما يقرا الصورة تاني.

**العملة الافتراضية الجنيه.** الفورم الفاضي بيقترح دولار لأن معظم
الاستيراد بيه، لكن المسح لأ: ورقة من غير عملة مكتوبة غالبًا فاتورة
محلية، وافتراض الدولار بيحوّل ٥٠٠ جنيه لـ ٥٠٠ دولار في صمت. لو المورد
اتطابق بتتاخد عملته، وإلا جنيه بسعر صرف 1.

- **فاتورة البيع** لو البند مش مكتوب فيه سعر، بياخد سعر الصنف حسب شريحة
  التاجر (جملة الجملة أو تجزئة) وبيتلوّن أصفر عشان تراجعه.
- **المسح بيعمل مسودة، مش فاتورة.** المسودة حالتها `draft` وما بتلمسش
  المخزون ولا أرصدة التجار ولا الخزينة ولا عمولة المندوب. ده مجاني
  تقريبًا في النظام: كل استعلامات الأرصدة والتقارير بتفلتر على
  `confirmed` أصلاً.
- **صفحة المراجعة**: الفورم العادي متملّي، وجنبه صورة الفاتورة (بتدوير
  وتكبير — الصور بتتصوّر بالموبايل مايلة)، وتحته «حفظ كمسودة» و«تأكيد
  الفاتورة». التأكيد بس هو اللي بيشغّل `InvoiceService` العادي.
- **الزرار موجود على صفحات القوايم كمان** جنب «فاتورة بيع جديدة»،
  والمسودات بتبان في القايمة بعلامة «مسودة» وليها فلتر، وبره الإجماليات.
- **الصورة بتتعلّق على المسودة** وبتنتقل للفاتورة المؤكّدة مع التأكيد.

### الاختبارات

اختبارات الجزئين بتزيّف المزوّد بالكامل (`Prism::fake()`) — ولا اختبار
بيلمس شبكة ولا محتاج مفتاح API:

```bash
php artisan test --filter=Ai
```

### السرعة على الاستضافة المشتركة

حد تنفيذ PHP على Hostinger حوالي 30 ثانية، والمحادثة بتعمل أكتر من نداء
لما الموديل يطلب أداة. عشان الشاشة ما تعلّقش:

- **التفكير على أقل درجة في المحادثة** (`thinkingLevel: low` على Gemini).
  أسئلة زي «مين أكبر مديونية؟» مش محتاجة تفكير عميق. **مسح الفاتورة
  بيفضل على التفكير العادي** — الصورة المزحومة محتاجة وقت.
- **مهلة 20 ثانية للنداء الواحد، وميزانية 25 ثانية للطلب كله.** دورة
  الأدوات بتتدار في `AiService` مش جوه Prism (`withMaxSteps(1)` لكل
  نداء)، فقبل كل جولة بنحسب الوقت الفاضل ونديه للنداء الجاي. لو الوقت
  خلص بنرمي رسالة عربية بنفسنا بدل ما PHP يقطع ويطلّع صفحة 500 بيضا.
- **التعليمات قصيرة** — وصف كل أداة والـ schema بتاعها بيتبعتوا مع
  الأدوات نفسها، فالشرح الطويل بتاع سيرفر الـ MCP مش بيتكرّر في كل جولة.
- **تاريخ المحادثة آخر 6 رسايل بس** — كل رسالة زيادة توكنز ووقت.
- **زرار الإرسال والأسئلة المقترحة بيتقفلوا** وهو بيفكّر، فالسؤال
  ما يتبعتش مرتين.
- **المحادثة على الموديل الخفيف** (`gemini-3.5-flash-lite`) — ده لوحده
  اللي نزّل الرد من دقيقة لثواني.
- **503 بيتعاد مرة، وبعدين بيتحوّل للموديل البديل**، ونفس الحكاية لو
  الموديل رجّع 404.
- **ولو الموديل اتأخر، بيتحوّل للبديل على طول** من غير ما يعيد المحاولة
  على نفس الموديل — اللي اتأخر مرة هيتأخر تاني، وإعادة المحاولة عليه
  بتاكل اللي فاضل من الميزانية. والتحويل ده بيحصل بس لو فاضل وقت يكفي
  نداء جديد؛ غير كده المستخدم بياخد رسالة «المساعد أخد وقت أطول من
  اللازم» على طول.
- **أعطال المساعد بتتسجّل بمستوى `error`**، فبتبان على السيرفر وهو
  مظبوط على `LOG_LEVEL=error`.

## طلبات التحضير

ورقة بتروح للمخزن يجهّز عليها بضاعة تاجر قبل ما الفاتورة تتكتب.
«الحركة اليومية ← طلبات التحضير».

### مفيش أسعار — ولا في مكان واحد

لا على الشاشة، لا في الـ PDF، لا في الورقة المطبوعة، **ولا حتى في
البيانات اللي بتتبعت للمتصفح**. الكتالوج اللي بيغذّي منتقي الأصناف
مشترك مع فاتورة البيع وفيه تلات أعمدة أسعار، فالكنترولر بيشيلها قبل
ما يبعته — مش معتمدين على إن الواجهة مش هتعرضها.

السبب بسيط: الورقة بتتطبع وبتروح لعامل المخزن، وبتتبعت على الواتساب
للسواق. محدش فيهم محتاج يعرف التاجر بيشتري بكام.

السعر بيدخل الصورة في خطوة واحدة بس — وقت التحويل لفاتورة بيع.

### الحجز — ده أهم جزء

الطلب **المفتوح** أو **المحضّر** بيحجز الكميات: بيخصم من «المتاح» في
النظام كله من غير ما يعمل أي حركة مخزون. البضاعة لسه على الرف، بس محدش
ينفع يبيعها.

المتاح ده بيظهر في:

- منتقي الأصناف في طلب التحضير — والصنف اللي متاحه صفر **بيبان ومتقفل**
  مش بيتشال. لو اتشال، اللي بيكتب الطلب بيفضل بيدوّر عليه وبيفتكر إن
  فيه غلط في الكتالوج.
- شاشة المخزون — عمود للمحجوز وعمود للمتاح جنب الرصيد.
- فورم فاتورة البيع، **وفحص الحفظ نفسه**: فاتورة بتحاول تاخد بضاعة
  محجوزة بتترفض برسالة بتقول «فيه كذا محجوزة بطلبات تحضير» — من غير
  الجملة دي المستخدم بيبص على المخزن، بيلاقي البضاعة، ومش فاهم.

الحجز بيتفكّ بالإلغاء أو بالتحويل لفاتورة. الإلغاء مابيعملش أي حركة
مخزون.

### الحالات

| الحالة             | بتحجز؟ | يعني إيه                           |
| ------------------ | ------ | ---------------------------------- |
| مفتوح              | ✅     | اتفتح لسه، المخزن ما بدأش          |
| تم التحضير         | ✅     | المخزن جهّزه وممكن يكون عدّل الكميات |
| تم التحويل لفاتورة | ❌     | البضاعة اتخصمت بالفاتورة فعلاً       |
| ملغي               | ❌     | اتلغى من غير أي حركة مخزون         |

### المخزن بيعدّل الكميات

عامل المخزن بيلاقي الصنف ناقص فبيعدّل المحضّر. الكمية المحضّرة بتتسجّل
في **عمود لوحدها** والمطلوب الأصلي بيفضل مكتوب — أول سؤال لما حد يختلف
على كمية هو «هو طلب كام وإحنا طلّعنا كام؟»، ولو دسنا على المطلوب السؤال
ده مابقاش ليه إجابة. والتعديل بيتسجّل في سجل النشاط بالاسم والكمية.

### الطباعة والـ PDF

ورقة A4 فيها رقم الطلب والتاجر والتاريخ والمخزن، والأصناف بالكود والاسم
والوحدة والكمية، وخانة **«تم»** فاضية جنب كل صنف عشان اللي بيجمّع يعلّم
فيها بالقلم وهو ماشي على الرفوف، وتوقيعين تحت (حضّر / استلم).

### واتساب — من غير أي API

مفيش توكن ولا رقم مسجّل ولا قالب معتمد ولا سيرفر وسيط. الزرار بيفتح
واتساب اللي على الجهاز والمستخدم هو اللي يختار يبعت لمين:

- **على الموبايل**: `navigator.share` بملف الـ PDF نفسه، فالتاجر بيستلم
  الورقة كمرفق في الشات مش لينك يفتح متصفح.
- **على الكمبيوتر**: `wa.me` برسالة فيها ملخّص عربي قصير (الرقم والتاجر
  والأصناف وكمياتها) و**لينك موقّع** للـ PDF.

اللينك الموقّع (`URL::temporarySignedRoute`) بيفتح من غير تسجيل دخول —
ده اللي بيخلّي الحكاية تشتغل أصلاً — وبيقع لوحده بعد أسبوع، وأي تغيير
في حرف واحد فيه بيبطّله. ومفيش أسعار على الورقة، فأسوأ حاجة ممكن تتكشف
هي كميات طلب واحد.

### التحويل لفاتورة بيع

زرار «تحويل لفاتورة بيع» بيفتح **نفس شاشة فاتورة البيع العادية** مش
نسخة تانية منها، متملّية بالتاجر والمخزن والبنود، والأسعار محسوبة من
شريحة التاجر (زي ما الفورم بيعمل لما تختار صنف بإيدك). الفاتورة اللي
جاية من طلب لازم تمشي بنفس قواعد أي فاتورة — الضريبة وفحص المتاح وتحذير
حد الائتمان — ونسختين من الفورم كانوا هيفرقوا عن بعض مع أول تعديل.

الحفظ بيعلّم الطلب «اتحوّل» ويفكّ الحجز **جوه نفس معاملة الفاتورة**،
فالبضاعة بتتخصم مرة واحدة بس، ولو الفاتورة وقعت لأي سبب الطلب بيرجع
مفتوح بحجزه زي ما كان. وفيه `lockForUpdate` على الطلب عشان طلبين في نفس
اللحظة ما يتحوّلوش لفاتورتين.

### الصلاحيات

`preparation-orders:manage` — للمدير والمحاسب **والمبيعات**. المندوب
بيفتح الطلب وهو واقف مع التاجر، ومفيش أسعار في الشاشة أصلاً فمفيش حاجة
حسّاسة بتتكشف. مستخدم من غير دور بياخد 403.

## سجل النشاط

كل حركة في النظام بتتسجّل: مين عملها وإمتى، ومع التعديلات «قبل/بعد» لكل
حقل اتغيّر. مبني على
[spatie/laravel-activitylog](https://spatie.be/docs/laravel-activitylog).

- **الدخول**: كل دخول وكل محاولة فاشلة، بالمستخدم والوقت والـ IP والمتصفح.
  الباسورد عمره ما بيتسجّل. و`users.last_login_at` بيتحدّث مع كل دخول.
- **حركات البيزنس**: إضافة وتعديل وحذف وتأكيد وإرسال للمنظومة على
  الفواتير والمسودات والسندات والأصناف والتجار والموردين والمخازن
  والمستخدمين. الفواتير والسندات أصلاً فيهم `user_id` — هو ده اللي
  سجّلها.
- **الشاشة**: «سجل النشاط» تحت المستخدمين، **للمدير لوحده**، بفلاتر على
  المستخدم والحركة والكيان والمدة، والأحدث فوق.

### الصلاحيات

المدير بيشوف نشاط أي حد. باقي الأدوار بيشوفوا نشاطهم هما بس — في الشاشة
وفي المساعد. ده أضيق من باقي النظام عن قصد: «مين عدّل السعر ده؟» سؤال
إداري مش بيانات شغل.

### التقليم

السجل بيتحفظ **12 شهر**:

```bash
php artisan erp:prune-activity            # بيمسح الأقدم من سنة
php artisan erp:prune-activity --dry-run  # بيعدّ بس
php artisan erp:prune-activity --months=6
```

سطر الكرون في hPanel (مرة كل شهر، أول يوم 3 الفجر):

```
0 3 1 * * /usr/bin/php /home/USERNAME/domains/erp.usi-eg.com/artisan erp:prune-activity >/dev/null 2>&1
```

غيّر `USERNAME` باسم المستخدم بتاعك، وتأكد من مسار PHP من hPanel
(ساعات بيكون `/opt/alt/php84/usr/bin/php`).

### أدوات المساعد

| الأداة             | بتعمل إيه                                       |
| ----------------- | ----------------------------------------------- |
| `recent-activity` | آخر الحركات، بفلتر على المستخدم والحركة والكيان |
| `last-login`      | آخر دخول لكل مستخدم ومن أنهي IP                 |
| `who-did`         | تاريخ سجل واحد: «مين عمل S-2026-00001؟»         |

متاحة في «اسأل السيستم» وعلى سيرفر الـ MCP، وبنفس الصلاحيات.

## تحميل PDF وإكسيل

جنب كل زرار طباعة فيه زرار **تحميل**: التقارير، وكشوف التجار
والموردين، وفواتير البيع والشراء (الفاتورة لوحدها والقائمة كلها)،
وجداول الوكلاء. صفحات الطباعة فاضلة زي ما هي — الطباعة للورق،
والتحميل للإرسال والأرشفة.

**التحميل بياخد فلاتر الشاشة الحالية.** الفترة والبحث وباقي الفلاتر
بيتبعتوا مع الرابط، فالملف المحمّل هو نفسه اللي قدام المستخدم بالظبط.
ولو كان مفلتر، ترويسة الملف بتقول كده — عشان اللي بيستلمه ما يحسبهوش
كامل.

وقوايم الفواتير بتتحمّل بـ**كل النتيجة مش الصفحة المعروضة**: الشاشة
بتعرض عشرين فاتورة في الصفحة، والملف بياخد كل اللي الفلاتر بتجيبه.
الشاشة والملف بياخدوا الاستعلام من نفس الخدمة (`SalesQueryService` و
`PurchaseQueryService`) عشان ما يبقاش فيه نسختين من نفس الفلاتر
يفرقوا عن بعض مع أول تعديل.

### رقم الفاتورة في الكشوف

كشف التاجر وكشف المورد فيهم عمود **رقم الفاتورة**، وفوقهم خانة بحث
بيه. سؤال «التاجر بيقول إنه دفع الفاتورة الفلانية، فين؟» كان بيتجاوب
بالتدوير بالعين في كشف من مية سطر.

البحث بيشتغل **بعد** حساب الرصيد الجاري مش قبله: السطر اللي بيظهر
بيفضل شايل رصيده الحقيقي من الكشف الكامل، والافتتاحي والختامي
والإجماليات بتفضل على الفترة كلها — فالكشف يفضل مقفول حتى وهو مفلتر.
ولو اتفلتر الأول، كل رقم في عمود الرصيد كان هيبقى مالوش معنى.

وقوايم الفواتير (مبيعات ومشتريات) بيتدوّر فيها برقم الفاتورة أو باسم
الطرف من نفس خانة البحث.

### PDF

مبني على [mPDF](https://mpdf.github.io) لأنه الوحيد اللي بيشكّل العربي
صح (`dompdf` بيطلّع حروف مقطّعة — ده كان سبب إن النظام فضل فترة بيطبع
من المتصفح بس).

- **خط Tajawal متضمّن في المشروع** (`storage/fonts/Tajawal-Regular.ttf`
  و`Tajawal-Bold.ttf`)، مش معتمد على خط موجود على السيرفر — استضافة
  مشتركة مش مضمون فيها أي خط عربي.
- A4 عمودي، RTL، هيدر فيه اسم الشركة واسم المستند والفترة، وفوتر فيه
  «صفحة 1 من 5».
- **النص نص حقيقي مش صورة**: ينفع تحدّده وتنسخه وتدوّر فيه، والأرقام
  لاتينية زي باقي النظام.
- أول PDF بعد كل نشر بياخد ثانية زيادة عشان mPDF بيحلّل الخط ويخزّن
  التحليل في `storage/app/mpdf`؛ بعدها مابيتكررش.

#### الخط لازم يفضل ثابت (static) مش متغيّر (variable)

mPDF مابيعرفش الخطوط المتغيّرة. لو حطّيت واحد، بيحاول يقرا جداول GSUB
بتاعته وبيقع بـ `Undefined array key 0` جوه `TTFontFile`، و**كل** PDF في
النظام بيرجّع 500.

وده بالظبط اللي حصل مع Cairo: فوق المنبع مابيتوزّعش غير كملف متغيّر
واحد (`Cairo[slnt,wght].ttf`). العطل ماكانش باين محليًا لأن كاش الخط
في `storage/app/mpdf` كان دافي على جهاز التطوير، والسيرفر بيبدأ بكاش
فاضي.

لو عايز ترجّع Cairo، ولّد منه نسخ ثابتة الأول واعمل لها commit:

```bash
pip install fonttools
fonttools varLib.instancer -o storage/fonts/Cairo-Regular.ttf "Cairo[slnt,wght].ttf" wght=400 slnt=0
fonttools varLib.instancer -o storage/fonts/Cairo-Bold.ttf    "Cairo[slnt,wght].ttf" wght=700 slnt=0
```

`ExportTest` بيحرس الحتّة دي من تلات نواحي: بيرفض أي ملف خط فيه جدول
`fvar`، وبيمسح كاش الخط قبل ما يرسم عشان القراءة تحصل من أول وجديد،
وبيتأكّد إن اسم الخط المحقون في الـ PDF هو خطنا إحنا.

#### الخط المتضمّن هو اللي بيترسم بيه فعلاً

`autoLangToFont` مقفول في `PdfService` عن قصد. وهو مفتوح، mPDF بيقرا
`lang="ar"` من القالب وبيستبدل خطنا بخط XB Riyaz اللي جواه هو — فالخط
اللي ضامّينه للمشروع مابيتستعملش أصلاً وكل الـ PDF بتطلع بخط تاني من
غير أي تنبيه.

### إكسيل

ملف `.xlsx` حقيقي متكتب بـ `ZipArchive` اللي جوه PHP — **من غير أي
مكتبة زيادة**. ملف الإكسيل في الآخر زِب فيه كام ملف XML، وكتابته
بإيدنا أرخص بكتير من إضافة PhpSpreadsheet على استضافة مشتركة عشان جدول
من عشر أعمدة.

الأرقام بتتكتب كأرقام مش نصوص، فإكسيل بيجمعها. والورقة RTL.

لو `ZipArchive` مش موجودة لأي سبب، بيرجع CSV بـ **BOM** — من غيره
إكسيل بيقرا العربي رموز مكسّرة.

### متطلبات السيرفر

`ext-gd` (لـ mPDF) و`ext-zip` (للإكسيل) لازم يكونوا مفعّلين من hPanel.
لو الـ CLI مش بيحمّلهم، شغّل الأوامر بـ
`php -d extension=gd -d extension=zip`.

## التنبيهات

### المشغّلات

- **صنف نزل تحت حد الطلب** — بيتبعت **مرة واحدة عند العبور**، مش مع كل
  بيعة. من غير القاعدة دي صاحب المحل بيتقفل عليه عشرين رسالة في اليوم
  ويقفل التنبيهات كلها أول أسبوع. `stock_alert_states` بيفتكر حالة كل
  صنف، والتنبيه بيترجع بس لما الرصيد يطلع فوق الحد وينزل من جديد.
- **صنف خلص** — أول ما يوصل صفر. بيكسب على «قرب يخلص» عشان ما يجيش
  رسالتين على نفس الحاجة.
- **ملخّص يومي 9 الصبح** — كل النواقص في رسالة واحدة.

إضافة تنبيه جديد (حد الائتمان، البيع تحت التكلفة، المتأخرات) = سطر في
`config/notifications.php` + كلاس `Notification`. من غير migration ولا
تعديل في الواجهة.

### القنوات

| القناة            | بتشتغل لما                                      | افتراضيًا   |
| ----------------- | ----------------------------------------------- | ---------- |
| **داخل النظام**   | دايمًا — الجرس في الشريط العلوي، غير المقروء فوق | **مفتوحة** |
| **إيميل**         | إعدادات `MAIL_*` متظبّطة                         | مقفولة     |
| **إشعار المتصفح** | `VAPID_*` متظبّطة، والمستخدم سمح من الزرار       | مقفولة     |
| **واتساب**        | `WHATSAPP_*` متظبّطة، والرقم متأكّد               | مقفولة     |

**الجرس بس هو اللي شغّال من غير أي إعداد** — لا `MAIL_` ولا `VAPID_` ولا
`WHATSAPP_` ولا حتى كرون. التنبيه بيتكتب في قاعدة البيانات **في نفس
اللحظة** اللي الرصيد بينزل فيها تحت الحد (`Notification::sendNow`)، جوّه
الريكوست نفسه.

القنوات التانية بتدخل الطابور لأنها نداءات شبكة — مش ينفع المستخدم
يستنى عليها وهو بيحفظ فاتورة. والقناة اللي مفاتيحها ناقصة **مابتظهرش
خالص** في «إعدادات التنبيهات»: خيار معطّل بيخلّي المستخدم يسأل «ليه ده
مقفول؟»، واللي مش موجود مابيسألش.

كل مستخدم بيظبّط اللي يوصله من **«إعدادات التنبيهات»**. المستقبلين
افتراضيًا: **المدير والمحاسب**.

### إشعارات المتصفح

```bash
php artisan erp:vapid-keys   # بيطبع المفاتيح، حطّهم في .env بإيدك
```

الإذن بيتطلب من زرار في صفحة الإعدادات بس — **عمرنا ما بنطلبه تلقائيًا**.
المتصفحات بتعاقب على ده، والمستخدم بيرفض من غير ما يفهم بيرفض إيه.

### واتساب

Meta Cloud API الرسمي، و**قوالب معتمدة مش رسايل حرة** — واتساب مابيسمحش
تبعت رسالة حرة لحد مابدأش محادثة معاك في آخر 24 ساعة. القناة مقفولة
تمامًا لحد ما `WHATSAPP_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID` يتحطوا.

### الجدولة على استضافة مشتركة

تنبيهات الجرس **مش محتاجة الكرون ده خالص** — بتتبعت فورًا وقت الحركة.
الكرون للملخّص اليومي والقنوات الخارجية وتقليم السجل:

```
* * * * * /opt/alt/php84/usr/bin/php /home/u402136675/domains/usi-eg.com/erp-system/artisan schedule:run >> /dev/null 2>&1
```

**كرون واحد بس** — وهو اللي بينادي:

| المهمة           | الميعاد                            |
| ---------------- | ---------------------------------- |
| تفريغ الطابور    | كل دقيقة (مع `withoutOverlapping`) |
| ملخّص النواقص     | كل يوم 9:00                        |
| تقليم سجل النشاط | أول كل شهر 3:00                    |

**كل المهام بتشتغل جوّه نفس العملية.** `Schedule::command()` بيفتح عملية
PHP جديدة عن طريق `proc_open`، و`proc_open` و`exec` مقفولين على
Hostinger — يعني أي مهمة بـ `command()` هتفشل في صمت على السيرفر. فكل
حاجة في `routes/console.php` بـ `->call()`: إما نداء مباشر للخدمة، أو
`Artisan::call()` اللي بينفّذ الأمر في نفس العملية.

`ScheduleTest` هو الحارس: أي مهمة جديدة تتكتب بـ `command()` هتكسر
الاختبار قبل ما توصل الإنتاج.

## اسأل السيستم من على واتساب

نفس الموجّه ونفس المجالات ونفس الصلاحيات بتاعة الشات في الموقع — الفرق إن السؤال
جاي من رسالة واتساب والرد بيرجع عليها.

### الحارس

**الرقم لازم يكون مربوط بحساب مستخدم ومتأكّد منه.** أي رقم تاني
مابياخدش رد خالص — مش رسالة رفض، ولا حتى تأكيد إن في نظام هنا. حد
بيجرّب أرقام عشوائية مالوش حق يعرف إن في حاجة على الطرف التاني.

الربط من صفحة الملف الشخصي: تكتب الرقم، بيجيلك كود على الواتساب،
تكتبه، يتربط. الكود صالح 10 دقايق، والرقم الواحد لحساب واحد بس.

الدور بيتطبّق زي الموقع بالظبط: مندوب المبيعات مش هياخد من على
واتساب حاجة مش شايفها على الشاشة.

### الرد

- **قصير** — جملة أو جملتين، الرسالة بتتقرا على موبايل.
- **في الطابور** — واتساب بيستنى 200 في ثواني وإلا بيعيد الإرسال،
  والموديل بياخد وقته. فالويبهوك بيرد 200 على طول والرد بيتعمل بعدين.
- **مفيش تاريخ محادثة** — كل رسالة سؤال مستقل. سؤال متابعة من غير
  سياق أحسن من سياق غلط من ساعتين.
- نفس حد الاستخدام بتاع الشات لكل مستخدم.

### الإعداد على Meta

1. في Meta for Developers → WhatsApp → Configuration، حط الويبهوك:
   `https://erp.usi-eg.com/ai/whatsapp/webhook`
2. الـ Verify token = اللي في `WHATSAPP_VERIFY_TOKEN`.
3. اشترك في حقل `messages`.

مقفول تمامًا لحد ما `WHATSAPP_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID`
يتحطوا في `.env`.
