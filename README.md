# نظام إدارة التوزيع — ERP

نظام ERP بالعربي (RTL) لشركة استيراد وتوزيع مصرية: مشتريات بعملات أجنبية مع مصاريف
استيراد، مخازن، مبيعات للتجار، تحصيلات، مندوبين، وتقارير.

**Laravel 13 · Inertia v3 · Vue 3 + TypeScript · Tailwind v4 · MySQL (InnoDB)**

---

## التشغيل

```bash
composer install
npm install
cp .env.example .env && php artisan key:generate
php artisan migrate --seed
npm run dev
```

### وضعين للبيانات

| الأمر | بيعمل إيه |
| --- | --- |
| `php artisan db:seed` | **نظام فاضي للتسليم**: 3 مستخدمين بأدوارهم وفريق الشركة وبس. **ولا مخزن ولا تصنيف ولا صنف ولا تاجر ولا مورد ولا أي حركة.** |
| `php artisan db:seed --class=DemoSeeder` | **بيانات تجريبية كاملة**: 2 مخازن، 6 تصنيفات، 40 صنف، 5 موردين، 25 تاجر، 4 مندوبين، و3 شهور حركة بيع وشراء وتحصيل ومرفقات. |

الوضع الافتراضي مكتوب من غير `factory()` ولا `fake()`، فبيشتغل على السيرفر بعد
`composer install --no-dev` (مكتبة Faker موجودة في `require-dev` بس). وآمن لو
اتشغّل أكتر من مرة — بيتخطّى أي مستخدم موجود.

`DemoSeeder` بيمسح بيانات النظام الأولى قبل ما يشتغل، فينفع تشغّله فوق النظام
الفاضي على طول — المستخدمين ما بيتمسوش.

### البدء من نظام فاضي

كل شاشة بتعرض حالة فاضية بالعربي مع زرار إجراء بدل أصفار ورسوم فاضية، ولوحة
التحكم بتعرض خطوات التشغيل. أول خطوة عملية هي **المخازن** من القائمة الجانبية
← «أضف أول مخزن»، لأن كل حركة شراء أو بيع لازم تتسجّل على مخزن.

| -------------- | --------------------- | ---------- | ---------- |

## قواعد مهمة في البيانات

- **رصيد المخزن = مجموع حركات المخزون** (`stock_movements`)، مفيش عمود رصيد مخزّن.
- فواتير الشراء بعملتها + `exchange_rate` للتحويل للجنيه. `stock_movements.unit_cost`
  **دايمًا بالجنيه** بعد توزيع مصاريف الاستيراد على البنود.
- أرصدة الموردين بعملة المورد؛ أرصدة التجار ومصاريف الاستيراد بالجنيه.
- عمولة المندوب بتتحسب **على المحصّل** مش على المبيعات.
- كل الأرقام بأرقام لاتينية (0-9) والتواريخ بصيغة «13 نوفمبر 2026».
- توقيت التطبيق `Africa/Cairo` (يتغيّر من `APP_TIMEZONE` في `.env`).

## سيرفر الـ MCP — ربط كلود بالبيانات

النظام فيه سيرفر [MCP](https://modelcontextprotocol.io) **للقراءة فقط**، بيدّي كلود
القدرة إنه يجاوب على أسئلة زي «مين أكبر المديونيات؟» أو «إيه اللي ناقص من المخزن؟»
من غير ما يقدر يعدّل أي حاجة. كل الأدوات متعلّمة `readOnlyHint`.

### الأدوات

| الأداة                | بتعمل إيه                                                          |
| -------------------- | ------------------------------------------------------------------ |
| `low-stock-products` | الأصناف تحت حد الطلب والناقص من كل صنف                              |
| `trader-balance`     | رصيد تاجر، المحصّل منه، وحالته مع حد الائتمان                        |
| `top-debtors`        | أكبر المديونيات + إجمالي المستحق على كل التجار                     |
| `sales-summary`      | مبيعات فترة مقسّمة باليوم أو بالشهر                                 |
| `top-products`       | أكتر الأصناف مبيعًا بالقيمة أو بالكمية مع هامش الربح                 |
| `stock-lookup`       | رصيد صنف في كل مخزن + التكلفة وسعر البيع                           |
| `invoice-lookup`     | تفاصيل فاتورة برقمها: البنود، الإجماليات، وحالة الفاتورة الإلكترونية |

### الاتصال

السيرفر على `POST https://erp.usi-eg.com/mcp/erp`، ومحمي بجارد Passport واحد
(`auth:api`) بيقبل طريقتين للتوكن.

#### 1) claude.ai على الويب — Custom Connector (OAuth 2.1)

في claude.ai: **Settings → Connectors → Add custom connector**، والصق:

```
https://erp.usi-eg.com/mcp/erp
```

كلود بيكتشف الباقي لوحده: بيقرا `/.well-known/oauth-protected-resource/mcp/erp`،
بيسجّل نفسه على `/oauth/register`، وبيحوّلك على `/oauth/authorize` — تدخل
بحساب النظام وتضغط **«اسمح بالوصول»**، وبترجع لكلود متوصّل.

المسارات اللي `Mcp::oauthRoutes()` بتسجّلها:

| المسار                                          | وظيفته                                 |
| ----------------------------------------------- | -------------------------------------- |
| `/.well-known/oauth-protected-resource/mcp/erp` | بيقول لكلود مين سيرفر التصاريح         |
| `/.well-known/oauth-authorization-server`       | عناوين authorize/token/register + PKCE |
| `POST /oauth/register`                          | تسجيل العميل تلقائيًا (RFC 7591)        |
| `GET /oauth/authorize`                          | شاشة الموافقة العربية                  |
| `POST /oauth/token`                             | تبديل الكود بتوكن (PKCE S256)          |

نطاقات الـ redirect المسموح بيها محصورة في `config/mcp.php` على `claude.ai`
و `claude.com` و localhost.

#### 2) Claude Code — توكن شخصي

```bash
php artisan erp:mcp-token admin@erp.test
```

الأمر بيطبع التوكن **مرة واحدة بس** ومعاه سطر الربط الجاهز:

```bash
claude mcp add --transport http erp https://erp.usi-eg.com/mcp/erp \
  --header "Authorization: Bearer <التوكن>"
```

#### محليًا من غير توكن (stdio)

```bash
php artisan mcp:start erp
php artisan mcp:inspector erp
```

### النشر على استضافة مشتركة

النشر المعتاد: `git pull` → `composer install` → `php artisan migrate`.
بعد أول نشر بس، شغّل مرة واحدة:

```bash
php artisan erp:mcp-setup
```

بيولّد مفاتيح Passport (مش بتتحط في git) وبيعمل عميل التوكنات الشخصية.
آمن لو اتشغّل تاني — بيعمل الناقص بس.

ولو بتعمل `config:cache` على السيرفر، شغّل `php artisan optimize:clear` بعد
أول نشر عشان إعدادات الجارد الجديدة تتقري.

**شروط لازم تتحقق على السيرفر:**

- `ext-sodium` مفعّلة في PHP (Passport محتاجها). تأكد بـ `php -m | grep sodium`.
- `APP_URL=https://erp.usi-eg.com` في `.env` — روابط اكتشاف الـ OAuth بتتبني منها.
- الملفات المبنية (`public/build`) بتتعمل لها commit من الجهاز المحلي لأن
  السيرفر مافيهوش Node.

## ملاحظات على العرض التوضيحي

- **الفاتورة الإلكترونية (ETA) وهمية** — `EtaService` بيولّد UUID شكله حقيقي
  وبيحرّك الحالة، لكنه عمره ما بيتصل بمنظومة مصلحة الضرائب.
- **طباعة PDF من المتصفح** — في صفحات طباعة مخصّصة (A4) بدل مكتبة PDF، لأن
  `dompdf` مش بيشكّل العربي و `mPDF` محتاج `ext-gd` مش متاح هنا.
- **المرفقات** على القرص الخاص (`storage/app/private`)، والوصول ليها بيعدّي على
  مسار محمي بتسجيل الدخول.
